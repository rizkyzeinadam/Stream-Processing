KONTEKS
Repo ini adalah artefak eksperimen pembanding fault recovery Apache Flink dan
Apache Spark Structured Streaming. Naskah jurnal melaporkan angka pada Tabel 1
(recovery stabilization interval, throughput deficit, peak backlog) dan Tabel 2
(peak memory). Angka itu dihitung dari 18 CSV mentah (3 skenario x 3 replikasi x
2 framework).

Masalahnya: di repo ini definisi metrik ditulis lebih dari satu kali dan saling
berbeda, sehingga hasilnya tidak sama dengan Tabel 1. Tugasmu menyatukannya.

DEFINISI METRIK (JANGAN DIUBAH — ini yang dipakai naskah)
- Skenario dan waktu injeksi: single = 120 s, central = 120 s (komponen kembali 180 s),
  multi = 330 s.
- Pembacaan CSV: buang baris yang elapsed_seconds / load_rate / throughput bukan angka
  berhingga (NaN/inf). Dedup per detik (int(round(elapsed_seconds))), urut menaik.
  Kolom memory: kalau NaN, anggap sampel hilang, bukan nol. Kolom wajib divalidasi sekali
  di awal; kalau ada yang hilang, berhenti dengan pesan jelas.
- Baseline: rata-rata throughput pada jendela [fault - 60 s, fault).
- T1: sampel pertama dengan elapsed >= fault yang throughput-nya < 0,5 x baseline.
  Kalau seri tidak pernah turun sedalam itu, T1 = waktu injeksi.
- T2: sampel pertama dari 5 sampel berturut-turut dengan throughput >= 0,9 x beban yang
  berlaku saat injeksi. T2 dihitung DARI AKHIR jendela fault aktif, yaitu max(fault, t2_min)
  dengan t2_min = 180 s untuk skenario central dan None untuk lainnya.
- Interval recovery = T2 - T1 (detik). Kalau T2 tidak tercapai, interval = tidak ada.
- Throughput deficit = 1 - (integral throughput) / (integral beban) sepanjang run, dalam persen.
  Sampel selama jendela pelapor-mati (skenario central, t = 120-180 s) dihitung sebagai
  throughput NOL. Celah koleksi (selisih antar sampel > 30 s) dihitung sebagai dt = 1 s,
  jangan diekstrapolasi.
  Jendela pelapor-mati dideteksi dari footprint memori: kalau ada sampel di [fault, fault + 60 s]
  dengan memory < 0,5 x rata-rata memory 60 s pra-fault, maka jendelanya = [fault, fault + 60 s].
- Peak backlog rate = max(beban - throughput, 0) dalam msg/s. Laporkan untuk seluruh run.
- Peak memory = max(memory) per run (MB).
- Pembulatan: setengah-ke-atas (ROUND_HALF_UP) pada digit terakhir yang ditampilkan.
  Simpangan baku = simpangan baku SAMPEL (ddof = 1), bukan populasi.
  Rata-rata dan SD dihitung dari nilai per-run yang BELUM dibulatkan.
  Contoh: nilai 22,750 dibulatkan ke 1 desimal menjadi 22,8 (bukan 22,7).
